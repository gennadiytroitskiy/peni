# Расчёт пеней ЖКУ — ТСЖ/УК

## Запуск
```
pip install -r requirements.txt
python3 app.py
```
Откройте http://localhost:5000
Демонстрационный доступ: `admin / admin123` — смените пароль и `SECRET_KEY` до реального использования.

Через Gunicorn (как на хостинге):
```
gunicorn app:app
```
`init_db()` вызывается при импорте модуля, поэтому таблицы создаются и в этом режиме.

## Состав
- `peni_engine.py` — ядро: FIFO-гашение платежей, разбивка по отрезкам, три метода ставки, сверка данных, срок оплаты 10/15.
- `app.py` — Flask: вход по логину, SQLite, импорт/экспорт Excel, PDF, массовый расчёт.
- `templates/` — страницы входа и расчёта.
- `static/template_mass.xlsx` — шаблон реестра.
- `test_checks.py` — обязательная дата платежа, поведение сверки, лист «Сверка».
- `test_final.py` — три метода ставки на одном реестре, аванс, контроль сходимости.
- `test_advance.py` — авансы, частичный аванс, переплата, режимы сверки.
- `test_helpers.py` — поиск колонок по названию, чтобы тесты не зависели от порядка столбцов.

## Методы расчёта ставки
| Ключ | Что делает |
|---|---|
| `fixed95` (по умолчанию) | 9,5 % на весь период долга |
| `historical` | Ставка Банка России на каждый день; с 27.02.2022 — не выше 9,5 % |
| `on_payment_date` | Одна ставка на весь долг: действовавшая на день оплаты (для непогашенного — на дату расчёта) |

Метод указывается в каждом отчёте. Не полагайтесь на подпись «историческая», не проверив настройку: для долгов до 27.02.2022 методы дают разный результат.

## Массовый расчёт
Реестр `.xlsx` с листами:
- `Начисления`: `Лицевой счёт`, `Период`, `Начисление, ₽`, необязательные `Срок оплаты`, `Вид долга`.
- `Платежи`: `Лицевой счёт`, `Дата платежа` (обязательно), `Сумма платежа, ₽`.

Заголовки распознаются без учёта регистра; «е» и «ё» приравнены.

### Обязательная дата платежа
Если в листе «Платежи» не заполнена дата, расчёт останавливается с указанием строки и лицевого счёта. Без даты нельзя разграничить пеню за дни до оплаты и после — такой расчёт нельзя пересчитать и защитить в суде.

### Авансовые платежи и переплата
**Аванс** — платёж, поступивший раньше срока оплаты того периода, который он закрывает. Аванс — обычная ситуация, а не ошибка: он закрывает период заранее, и пени на закрытую часть не начисляются вообще. Если авансом закрыта только часть суммы, пени идут на непогашенный остаток, начиная с 31-го дня просрочки.

В отчёте такие суммы выделены отдельно:
- в Сводке и Детализации — колонка **«в т.ч. авансом, ₽»**;
- на листе «Платежи» — колонка **«Вид»**: `аванс`, `в срок оплаты` или `с просрочкой`;
- в примечании к периоду: «аванс: 1 000,00 ₽ внесено до срока оплаты — пеня начислена только на неоплаченную часть».

**Переплата** — платежей по лицевому счёту больше, чем начислено. Разница, которую не удалось распределить по периодам, показывается колонкой **«Переплата, ₽»** и в ней же учитывается.

### Сверка и защита от двойного вычета
До расчёта суммы платежей и начислений сверяются по каждому лицевому счёту. Превышение платежей над начислениями бывает двух видов, и различить их по суммам нельзя:

| Ситуация | Как ведёт себя расчёт |
|---|---|
| Аванс или переплата — нормальная ситуация | **предупреждение**, расчёт продолжается, разница показана как аванс/переплата |
| В «Начислениях» указан остаток долга вместо полного начисления, а платежи приложены отдельно (суммы вычитаются дважды) | в режиме **«Запретить»** — расчёт останавливается |

Режим выбирается в форме загрузки: селект **«Авансовые платежи (переплата)»** — «Разрешить» (по умолчанию) или «Запретить». Режим «Запретить» полезен при переносе данных, когда нужно убедиться, что в «Начислениях» полное начисление, а не остаток.

При остановке в строгом режиме ответ выглядит так:
```
Расчёт остановлен — данные не согласованы:

ЛС ЛС-0001: платежей больше, чем начислено, на 1,400.00 ₽
(начислено 600.00, оплачено 2,000.00). Проверьте лист «Начисления»:
если там остаток долга, а не полное начисление, суммы вычтутся дважды.
Если это действительно аванс или переплата — выберите режим
«Разрешить авансы».
```

### Листы результата
1. **Сводка** — по лицевому счёту: начислено, оплачено (в т.ч. авансом), остаток, переплата, дни просрочки, дни с пенями, пени, применённые ставки, примечания с указанием периода.
2. **Детализация** — по периодам, с колонкой «в т.ч. авансом».
3. **Разбивка** — каждый отрезок: база, доля ставки (1/300 или 1/130), ставка, дни, сумма. Пересчитывается вручную.
4. **Платежи** — в какие периоды зачислены деньги, вид платежа (аванс / в срок / с просрочкой) и остаток после каждого зачисления.
5. **Сверка** — сопоставление начислений и платежей по каждому счёту.
6. **Контроль** — сверка «итог пеней = сумма отрезков».

## Срок оплаты
ФЗ от 24.06.2025 № 177-ФЗ (вступил в силу 01.03.2026): плата вносится до 15-го числа месяца, следующего за истекшим. Для сроков, наступивших до 01.03.2026, действует прежнее правило — до 10-го числа.
Публикация: https://publication.pravo.gov.ru/document/0001202506240048

## Границы начисления
- Дни 1–30 просрочки — без пеней.
- Дни 31–90 — 1/300 ставки за каждый день.
- С 91-го дня — 1/130 (для капремонта не применяется).

## Что важно проверить перед применением
1. **Метод ставки для долгов до 27.02.2022.** Практика расходится: часть судов применяет ставку на день оплаты, часть — ставку соответствующего периода. Выбор закрепите внутренним регламентом и согласуйте с юристом.
2. **Ставка для взносов на капремонт.** Ограничение 9,5 % по постановлениям № 474 и № 329 — вопрос спорный: одни источники считают, что оно действует для капремонта до 31.12.2026, другие — что с 01.01.2025 не применяется. Уточните у юриста.
3. **Пени выше долга.** Отдельные строки дают пени больше остатка — суды снижают их по ст. 333 ГК РФ.
4. **Нулевой остаток при ненулевых пенях.** Требует даты и суммы платежа; примечание в отчёте это помечает.
5. **Таблица ставок** в `peni_engine.py` — демонстрационная выборка; сверьте по официальному архиву Банка России.

## Ограничения
1. История расчётов видна только создавшему её пользователю; управления пользователями через интерфейс нет.
2. Для одного лицевого счёта допускается один вид задолженности (ЖКУ либо капремонт).
3. Без переменной `DATABASE_URL` используется SQLite; на бесплатном хостинге файл может не сохраняться между деплоями.
4. Расчёт носит справочный характер: перед использованием в квитанциях и исках проверьте его по контрольным примерам и согласуйте с бухгалтерией и юристом.
